2. PRODUCT DEFINITION
SahamYar is an intelligent analysis assistant for the Iranian capital market.
Its intended scope includes market/instrument analysis, technical and
fundamental evidence, official disclosures/news, Iran macroeconomy,
geopolitical conditions, liquidity/market behavior and relevant
global/parallel markets.

The product must separate source facts, deterministic calculations and
AI interpretation. Any analytical opinion must expose its evidence,
uncertainty, time horizon and risks.

Explicitly out of scope:
- Personal portfolio management.
- User transaction recording/management.
- Personal cost basis or profit/loss calculations.
- Excel imports of personal transactions.
- Brokerage order placement or automatic trading.

4. IMPLEMENTED BACKEND SURFACE
- TSETMC instrument search and details.
- Price and daily-history retrieval.
- Instrument categories COMMON_STOCK, RIGHTS, FUND, DEBT and OTHER.
- Technical indicators: SMA, EMA, RSI, MACD, Bollinger Bands, ATR,
  Stochastic, OBV, volume SMA and volume ratio.
- Codal report search/retrieval, parsing of five financial-statement
  structures and metric standardization.
- Overall market status, market-scoped status and instrument-scoped status.
- Calendar data and market-event handling with fail-closed behavior when
  the current calendar is missing or invalid.
- Sanitized provider-facing API errors.

Technical analysis is currently restricted to COMMON_STOCK and RIGHTS where
validated. Search support must not be confused with analysis support.

7. CURRENT LIMITATIONS
- Codal parsing and statement standardization exist; complete fundamental
  ratio calculations, multi-period comparisons and fundamental scoring
  are not finished.
- News, macroeconomic, geopolitical, liquidity/flow and global-market
  providers are not fully connected and verified.
- The current analysis API uses INSUFFICIENT_DATA as its recommendation
  action while the wider evidence set is incomplete. Do not claim a complete
  BUY/SELL/HOLD/WAIT recommendation engine.
- Price cache, subscriptions and scheduler state are in-memory.
- Durable watchlist/alert persistence, authentication/authorization and
  multi-worker scheduler coordination are incomplete.
- The scheduler starts through python -m app.main. WSGI imports do not run
  the module entry point; production worker lifecycle remains unresolved.
- Production deployment is deferred.
- Android/backend workflows need systematic device-level end-to-end testing;
  successful unit tests/build do not prove every UI flow is integrated.

8. DATA QUALITY RULES
- Missing data is not zero; never fabricate values or signals.
- Distinguish AVAILABLE, PARTIAL, UNAVAILABLE, INSUFFICIENT_DATA,
  UNSUPPORTED and ERROR.
- Preserve source, retrieved_at, as_of, units and report period/type.
- Mark cached values and timestamps.
- Do not turn model-generated interpretation into a source fact.
- Preserve conflicting evidence and uncertainty.
- Technical indicators alone are not guaranteed trading signals.
