PRODUCT SCOPE
SahamYar is an intelligent analysis assistant for Iran's capital market.
Its intended analysis covers instruments, market conditions, technical and
fundamental evidence, disclosures/news, Iran's economy, geopolitical risks,
and relevant global/parallel markets. Analytical opinions must include
reasons, uncertainty and risk; they are not trade execution instructions.

OUT OF SCOPE
- Personal portfolio management.
- Recording or managing user transactions.
- Personal cost-basis or profit/loss calculations.
- Excel transaction imports for personal holdings.
- Brokerage order placement or automatic trading.

IMPLEMENTED BACKEND CAPABILITIES
- Flask backend; Python 3.11+.
- TSETMC instrument search, instrument details, prices and daily history.
- Instrument categories are represented separately; technical analysis is
  currently supported only for COMMON_STOCK and RIGHTS where validated.
- Technical indicators include SMA, EMA, RSI, MACD, Bollinger Bands, ATR,
  Stochastic, OBV, volume SMA and volume ratio.
- Codal company/instrument report discovery, report retrieval, HTML parsing,
  five financial-statement structures and metric standardization.
- Market-hours and calendar handling, including market status and scoped
  market/calendar status endpoints.
- Price cache and background refresh scheduler with in-memory state.
- Sanitized public provider errors; detailed diagnostics remain in server logs.

KNOWN LIMITATIONS / NOT COMPLETE
- Codal statement parsing and standardization exist; a complete fundamental
  ratios, multi-period comparison and scoring engine is not complete.
- News, Iran macroeconomic, geopolitical, liquidity/flow and global-market
  data providers are not fully connected and verified. Their analysis layers
  must remain unavailable/partial rather than be inferred from model memory.
- The current stock-analysis API returns INSUFFICIENT_DATA as the recommendation
  action while the wider evidence set is incomplete; do not describe a complete
  BUY/SELL/HOLD engine as implemented.
- Price cache, subscriptions and scheduler state are in-memory.
- Durable watchlist/alert subscriptions, authentication/authorization and
  safe multi-worker scheduler coordination are not complete.
- Production deployment is deferred; local development server only.
- Android/backend end-to-end workflows still require systematic device-level
  verification beyond successful compilation and unit-test tasks.

DATA AND ANALYSIS RULES
- Missing data is not zero; never fabricate prices, metrics, events or signals.
- Distinguish provider facts, deterministic calculations and AI interpretation.
- Preserve source, retrieved_at, as_of, units and relevant report metadata.
- Label cached data and its timestamp.
- Use explicit statuses such as AVAILABLE, PARTIAL, UNAVAILABLE,
  INSUFFICIENT_DATA, UNSUPPORTED and ERROR.
- Preserve disagreement and uncertainty across sources and analysis layers.

MARKET CALENDAR NOTES
- Market status uses Asia/Tehran time and a local Jalali-year calendar file.
- Calendar validity is fail-closed: missing/invalid current-year calendar data
  must not be treated as a confirmed trading day.
- Market status routes include overall market, market-scoped and
  instrument-scoped responses.
- The market-events data file may contain no active events; do not infer
  special closures or warnings when none are recorded.
